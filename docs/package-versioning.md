# Package versioning — seeing what nix actually changed

"Version control the individual apps nix installs." The lock file can't do it: `flake.lock`
pins ~8 inputs, and the real dependency set (~7,700 packages on the desktop) only exists
after evaluation. A one-line lock bump silently changes hundreds of packages. This doc
covers the machinery that makes those changes visible — at review time, at switch time,
and retroactively.

## The case study that shaped the design

2026-07-06, generation 87 → 88 (a routine nixpkgs bump): portal screenshots regressed from
0.2s back to 2.1s. The culprit was `xdg-desktop-portal-hyprland` — but:

```
gen 87 → 88  (switched 2026-07-06 21:15:43)
  before: /nix/store/ps4965fk…-xdg-desktop-portal-hyprland-1.3.12
  after:  /nix/store/w61i8395…-xdg-desktop-portal-hyprland-1.3.12
```

**The version never changed.** xdph stayed at 1.3.12; only its *store path* moved — it was
rebuilt against a changed grim, and the grim baked into its wrapper PATH shadowed our `-l 0`
wrapper. No version-level diff (nvd, `nix store diff-closures`, or a manifest diff) can see
this class of change. The store-path hash can: it's a Merkle fingerprint of every build
input, so it changes exactly when *anything* that went into the package changed.

Hence two granularities, each covering the other's blind spot:

| | Version-level | Store-path-level |
|---|---|---|
| **Where** | `manifests/<host>.txt`, committed | this machine's kept generations |
| **Sees** | packages whose version changed | any rebuild, incl. same-version (the xdph case) |
| **Blind to** | same-version rebuilds | anything older than `gc`'s 14-day retention |
| **History** | permanent (`git log -p manifests/`) | local + temporary — git is the durable record |
| **Review surface** | every Renovate PR diff | `mise run whatchanged`, nvd at switch |

## Version-level: `manifests/`

`manifests/<host>.txt` is a sorted name-version inventory of each host's closure, generated
by `nix run .#gen-manifests` (eval-only — `nix path-info --derivation`, no build, so CI and
Renovate can run it). It is regenerated by:

- **`mise run verify`** — so every local change lands with fresh manifests;
- **Renovate's postUpgradeTasks** (both rules) — so every bump PR's diff literally shows
  "which apps changed, per host" — the review surface `flake.lock` can't provide;
- **CI (`check.yaml`)** — regenerates per host and `git diff --exit-code`s: stale manifests
  fail the build, so the committed files can't lie.

Answering "when did package X change, and in which commit?":

```sh
git log -p --follow manifests/desktop.txt | grep -B20 'xdg-desktop-portal-hyprland'
```

Caveats: the manifest is the **build closure** (eval-time superset — includes build-time
deps like compilers), the noise filters (archives, patches, `-source` FODs, loose script
files) are cosmetic, and there are **no timestamps** by design — CI's freshness gate and
Renovate's idempotent re-runs require byte-reproducible output.

## Store-path-level: switch-time diffs + `whatchanged`

- **Every activation prints an `nvd` diff** (`modules/system-diff.nix`) — old running
  system vs incoming config, so a rebuild never silently changes packages again.
  `nixos-rebuild dry-activate` previews it without switching.
- **Every generation is stamped with its git commit** (`system.configurationRevision`);
  read any past generation's: `/nix/var/nix/profiles/system-N-link/sw/bin/nixos-version
  --configuration-revision`. (Generations built before this module report `unknown`.)
- **`mise run whatchanged`** (or `nix run .#whatchanged`):
  - no args → version-level diff for every consecutive generation pair
    (`nix profile diff-closures`);
  - `PKG=<name>` → walks kept generations and reports every point where that package's
    store-path set changed, with switch date and config revision — the one-command answer
    to the xdph investigation. It found the gen 87→88 change *and* an earlier same-version
    rebuild (gen 66→67) nobody had noticed.

## Tooling notes

Both tools are flake apps built with `writeShellApplication`: shellcheck runs at build
time (a shell bug fails `nix flake check`), runtime deps are pinned via `runtimeInputs`,
and they run from anywhere — `nix run github:perfectra1n/nixos-configs#whatchanged -- <pkg>`
works on any machine with nix, no checkout needed. The script sources in `scripts/` are
*bodies only* (no shebang, no `set -euo pipefail` — writeShellApplication injects both).

**Public-repo consideration** (accepted): manifests make each host's package inventory
one-file greppable. This is not a new leak — the closure was always derivable by evaluating
the public flake — it just removes the effort barrier.
